# Malg — الأساس (قاعدة البيانات + تسجيل الدخول)

ده أول جزء من مشروع Malg، مبني من الصفر. اللي فيه دلوقتي:

- **schema.sql** — هيكل قاعدة البيانات (مستخدمين، جلسات، طلبات استرجاع الباسورد، سجل أدمن).
- **api/auth/signup.js** — تسجيل حساب جديد برقم + باسورد + اسم.
- **api/auth/login.js** — تسجيل دخول، مع حماية من محاولات الدخول الكتير الغلط (قفل مؤقت بعد 5 محاولات).
- **api/auth/me.js** — التحقق من الجلسة الحالية (يستخدم من الويب والأندرويد الاتنين لمعرفة هل المستخدم مسجل دخول ولا لأ).
- **lib/auth.js** — أدوات التشفير والتوكن.
- **lib/db.js** — الاتصال بقاعدة البيانات.

## خطوات التشغيل

1. اعمل مشروع جديد في **Neon** (https://neon.tech)، وخد الـ connection string.
2. شغّل محتوى `schema.sql` على قاعدة البيانات الجديدة (من Neon SQL Editor مباشرة، أو بأي أداة postgres).
3. اعمل نسخة من `.env.example` باسم `.env.local` واملأ القيم (`POSTGRES_URL` و `JWT_SECRET`).
4. `npm install`
5. انشر المشروع على Vercel وحط نفس متغيرات البيئة في إعدادات المشروع هناك.

## إزاي الويب أو الأندرويد يستخدموا الـ API ده

كل المنصات (ويب أو أندرويد) هتكلم نفس الـ API بنفس الشكل:

```
POST /api/auth/signup
Body: { "phone": "01xxxxxxxxx", "password": "......", "name": "الاسم" }
Response: { "user": {...}, "token": "jwt-token-here" }
```

```
POST /api/auth/login
Body: { "phone": "01xxxxxxxxx", "password": "......" }
Response: { "user": {...}, "token": "jwt-token-here" }
```

```
GET /api/auth/me
Header: Authorization: Bearer <token>
Response: { "user": {...} }
```

- تطبيق **الويب** هيحفظ الـ token في المتصفح ويبعته مع كل طلب.
- تطبيق **الأندرويد** هيحفظ الـ token في `SharedPreferences` (أو `EncryptedSharedPreferences` عشان أأمن) ويبعته بنفس الطريقة.

## الخطوة الجاية

بعد ما نتأكد إن التسجيل والدخول شغالين، الخطوة اللي بعد كده حسب ترتيبك:
- لوحة الأدمن (عرض المستخدمين، حظر، توثيق، مسح حساب).
- واجهة الدردشة الأساسية.
